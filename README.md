# YouTube 再生リスト自動化

YouTube の再生リストを動画 ID で比較し、追加先にまだない動画を条件で絞り込み、選択した動画をまとめて追加する日本語の Web アプリです。Vite、React、TypeScript で構築し、Google Identity Services と YouTube Data API v3 をブラウザから利用します。

## Google Cloud の設定

1. Google Cloud Console でプロジェクトを選び、**YouTube Data API v3** を有効にします。
2. **Google Auth Platform** で OAuth の同意画面を設定します。外部アプリがテスト状態の場合、使う Google アカウントを対象ユーザーの **テストユーザー** に追加します。公開時は、対象ユーザーと要求スコープに応じた Google の OAuth 検証を完了してください。
3. **ウェブ アプリケーション**の OAuth クライアントを作成し、**承認済みの JavaScript 生成元**に使うオリジンを登録します。
   - GitHub Pages は `https://ozakinico.github.io`
   - ローカル開発は `http://localhost:5173`
   - カスタムドメインを使う場合は、その HTTPS オリジンも登録
4. OAuth Client ID を控えます。生成元にはパスや末尾のスラッシュを含めません。ポップアップの token model を使うため、リダイレクト URI の設定は不要です。読み取りと追加に `https://www.googleapis.com/auth/youtube.force-ssl` を要求します。

Client ID はビルドに含まれる公開情報です。Client Secret、リフレッシュトークン、サービスアカウント鍵は使用しません。アクセストークンはページのメモリに保持し、ページの再読み込みや失効後は再認証が必要です。ログアウト時は Google にトークンの取り消しを要求し、メモリから消去します。

## ローカルで実行

Node.js 24 を推奨します（最低 22.12）。

```sh
npm ci
cp .env.example .env.local
# .env.local の VITE_GOOGLE_CLIENT_ID に OAuth Client ID を入力
npm run dev
```

ブラウザで `http://localhost:5173/youtube-playlist-automation/` を開きます。Client ID を変更したら開発サーバーを再起動してください。

## GitHub Pages に公開

1. リポジトリの **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選びます。
2. **Settings → Secrets and variables → Actions → Variables** にリポジトリ変数 `VITE_GOOGLE_CLIENT_ID` を作り、OAuth Client ID を設定します。
3. PR を `main` にマージすると、テストとビルドを通した成果物が Pages にデプロイされます。設定を後から追加した場合は **Actions** からワークフローを `main` で再実行できます。
4. 公開先は `https://ozakinico.github.io/youtube-playlist-automation/` です。

## 使い方

1. Google で認証し、コピー元を指定します。追加先は **自分の再生リストを取得** から、認証した YouTube チャンネルが所有するリストを選べます。URL や ID の入力でも指定できます。「比較のみ」を選ぶと追加や再開が無効になります。
2. **差分を取得**し、公開年、公開日、再生回数、動画の長さ、タイトルで絞り込みます。動画の長さは分単位で下限や上限を指定でき、**20分以上** ボタンで下限を設定できます。長さが不明な動画は長さ条件を設定した場合に除外されます。公開日と年は日本時間（Asia/Tokyo）で判定します。条件は AND で、上下限を含みます。取得できない動画・地域制限・再生回数欠損は別に表示します。
3. 動画を選択し、確認画面で追加先・対象・見積もりを確認して承認します。フィルターを変更しても手動選択は保持されます。確認画面に選択済みの全件が表示されます。
4. 追加結果で処理を停止または再開し、成功・失敗・スキップを確認します。候補全件、フィルター結果、追加結果は UTF-8 BOM 付き CSV で出力できます。

処理はブラウザを開いている間に実行されます。停止時には送信済みの操作が完了する場合があります。承認済みキューと処理結果は同じブラウザの localStorage に保存されます。再読み込み後は再認証して **再開** を押してください。新しい処理を承認すると前回の完了済み結果が置き換わります。追加処理は Web Locks API に対応する HTTPS または localhost のブラウザで動作します。同一ブラウザ内の複数タブでの同時追加を防ぎ、再開時や応答を確認できない時は追加先を取得してから再送を判断します。別ブラウザや YouTube 上で追加先を同時編集すると、API にアトミックな重複防止機能がないため、その同時変更までは防げません。

一覧取得は 50 件ごとのページ、メタデータ取得は 50 動画ごとのリクエストを使い、対象件数の上限は設けていません。読み取り 1 回につき 1、追加 1 回につき 50 クォータとして推計します。既定予算の 250,000 では読み取りや再試行を除くと理論上 5,000 件分です。画面の見積もりはそのページから送信した操作を集計した値で、他の操作による消費や Google Cloud の実残量は反映されません。

## 追加先への書き込みが拒否された場合

`playlistItemsNotAccessible`（403）は、YouTube が追加先への書き込みを許可しなかったことを示します。現在のチャンネルに書き込み権限があるか確認し、**自分の再生リストを取得**で対象のリストを探してください。別のチャンネルが所有している場合は、アプリからログアウトし、そのチャンネルで認証し直してください。対象が表示されない場合は、認証したチャンネルで YouTube 上に通常の再生リストを作成し、追加先に指定できます。

書き込み権限エラーが出たら、残りは送信せず保存します。同じ追加先に続ける場合は権限を確認して **再開** を押します。別の追加先に切り替える場合は、必要に応じて **追加結果 CSV** を保存してから **保存キューを破棄** し、新しい追加先で差分を取得し直してください。

## 検証

```sh
npm test
npm run build
```

ユニットテストは URL・ID 差分、JST の日付境界、フィルターの交差、再生回数の境界、欠損データ、CSV、安全なキュー再開を確認します。モック API で複数ページ・50 ID 超のメタデータ取得、読み取りの中断、書き込みの一時失敗・応答消失・認証失効・クォータ超過を検証します。

実アカウントでは、専用の小さなテスト用再生リストを使い、Google 認証 → 比較 → 1 件を選択して承認 → YouTube で追加結果を確認します。さらに処理中の停止・再読み込み・再認証・再開、差分の再取得で、追加済みの動画が重複しないことを確認してください。
